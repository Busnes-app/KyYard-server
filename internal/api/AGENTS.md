# API

## Purpose
Exposes HTTP REST routes, authentication endpoints, Single Sign-On callbacks, backup restore drill handlers, and static React PWA hosting.

## Ownership
Owns HTTP routing, request parsing, session cookie validation, CORS headers, and error response formatting.

## Local Contracts
- `/organizations/{organization}/environments/{environment}/applications`: GET lists bounded drafts; POST accepts only `{name, compose}` and creates revision 1 without runtime dispatch. GET `/{application}/revisions/{revision}` returns reference-only configuration; DELETE `/{application}` requires `{expected_revision}` and discards the draft/history. Store authorization gates each operation. Parser errors expose only fixed diagnostics/positions; never source, values or library errors. No secret-reveal HTTP route exists.
- Browser exec uses the tracked `GET /endpoints/{endpoint}/containers/{container}/exec` WebSocket. Require the exact advertised Origin, active tenant session and `container.exec` before upgrading; a strict first message within ten seconds must supply the CSRF cookie value, explicit user/argv, immutable container/image IDs, size and confirmed inventory name before any runtime dispatch. Commit store authorization and intent first, then send a nonce-bound 60-second grant on that exact agent socket. Eight-frame queues close on overflow; admission is four per endpoint, one per actor/endpoint, 32 per organization and 128 server-wide. Limit attempts to ten per actor/minute before the audited authorization check. Revocation bypasses the control queue with a 500 ms direct socket write and closes that exact socket on failure. Ordinary cleanup queues best-effort cancellation under the normal control-write budget; an agent-reported close needs no cancellation. Browser writes stall out after five seconds; ready waits ten seconds; input idle is 15 minutes and absolute lifetime eight hours. Ping every 25 seconds. Membership events, agent loss and shutdown cancel immediately; session/account/membership/endpoint checks run independently every 250 ms with a 500 ms deadline, failing closed; input frames check cancellation without querying the store. Close audit uses a detached two-second budget and records actor, scope, target, user, duration and inspected exit status; missing exit remains unknown. Terminal bytes, argv and agent error text never enter audit records. Attachment closure does not promise process termination.
- `RunLocalDocker` runs the existing agent client in-process over a private loopback listener exposing only the authenticated agent-connect route. Socket mounting is deployment authority; every browser operation still uses normal tenant authorization. Derive a domain-separated local identity from the persisted instance key, resume generation from SQL, persist only the command ledger in `data/local-agent`, and join local connection handlers before store shutdown. Disabled/missing sockets never block the rest of the server. The private listener has its own 20/minute connection budget, selected by server wiring; public per-IP traffic cannot consume it, and both listeners require the same authenticated handshake.
- Additional-host commands use one `sudo docker run --pull always` with `--link`, persistent identity/socket mounts and default bridge. Default image is the official repository digest of the installed server container image, discovered through Docker using the server hostname and immutable image ID. Only the current official repository is accepted. Discovery first checks store-owned `endpoint.enroll` authorization and environment scope; token creation rechecks authorization and persists the selected digest. Discovery is bounded to three seconds; missing socket/digest requires an explicit pinned `KY_AGENT_IMAGE` and produces no command. Overrides use the same digest policy. Only HTTPS advertised origins produce commands; HTTP returns setup guidance. No same-host inspect, shared network namespace or separate enrollment process is generated.
- Metrics frames are limited to `protocol.MaxMetricsBytes`; the agent shrinks honest frames before sending, and an oversized frame receives `metrics_too_large` while the session remains alive. Sample-budget exhaustion likewise returns an error frame without ending the session.
- Provider login/callback routes `/api/sso/{provider}/login|callback` require an enabled configured provider. Existing environment providers keep IDs `kysignon` and `oidc`; configured providers get immutable random IDs. Sync/SAML metadata still require `KY_SSO_ENABLED`.
- Admin-only `GET/POST /api/settings/sso` lists redacted provider configuration or creates a provider; `PUT /api/settings/sso/{provider}` rotates only the secret or changes availability without changing identity; `DELETE /api/settings/sso/{provider}` removes a UI-configured provider (existing sessions remain). The encrypted `sso_providers_enc` setting uses the deployment key with label `kyyard/sso/providers/v1`; it is included in the SQLite backup. Provider identity cannot be repointed to a different issuer. Local login is always available.
- SSO uses 5-minute, one-use server-side attempts (256 maximum with oldest-attempt eviction on admission, per-IP limit 10/minute), bound to provider ID and a random HttpOnly SameSite=Lax browser cookie, PKCE S256 and OIDC nonce. Restart expires pending logins. Provider errors never expose response bodies or credentials. New users have global role `user` and no tenant membership.
- SCIM and `/api/devices/` routes return JSON 404 even if inherited SCIM settings are enabled. Legacy tables remain for migration/recovery compatibility; recovery pairing is unrelated and remains supported.
- Public GET/HEAD `/health/live` reports process availability; `/health/ready` pings the store with a 2s deadline and returns 503 after `BeginShutdown`. Probes are no-store and never return backend errors.
- Unsafe requests with an Origin must match the configured advertised origin, including login/MFA; originless CLI/webhook requests still undergo their existing authentication/CSRF checks.
- POST `/api/auth/change-password` accepts a restricted local session, current password and a different policy-valid new password. Browser CSRF and per-IP/account limits apply. Success revokes all sessions and requires sign-in again; flagged sessions get `password_change_required` on protected routes and public-only settings.
- All JSON API endpoints return structured errors `{"error": "message"}` upon failure.
- Non-API routes fall back to serving `web.Handler()` for client-side SPA routing.
- New routes are unauthenticated only by deliberate choice; platform routes use `s.requireAdmin` (named `platform.admin` policy); tenant routes use `s.tenantRoute` and store-owned authorization.
- Backup routes and theme writes are admin-only: capsules and settings carry site data and secrets. The scaffold has no step-up; admin-only plus `TestPrivilegedEndpointsRequireAdmin` is its equivalent for every destructive backup route. Routes are registered with method patterns, and because the SPA catch-all answers any method, tests pin that a wrong method never reaches a backup handler rather than expecting 405.

- `POST /api/backup/deposit` is one `recoveryclient.Run`: seal once, deliver to the local directory and to KyRecovery when paired. 412 no key, key pin missing, no destination, no database snapshot, or a private destination with `KY_BACKUP_ALLOW_PRIVATE_RECOVERY` off; 409 key mismatch or a run in flight; 413 over the capsule caps; 502 when KyRecovery refused (`recoveryclient.ErrRemote`, naming a local copy that was written, so the `ErrPrivateDestination` arm must stay above it: the lib wraps both on the dial path); 500 for a failure before a byte left; 200 with `receipt_unrecorded` when the store holds the capsule but the receipt was not written. It runs on a context detached from the request with a 16-minute write deadline; the acting admin is resolved before the upload and the audit row is written on that same detached context.
- The write-once, irreversible backup handlers (`handlePairRemoteRecovery`, `handlePinKey`, `handleRunBackup`) run on `context.WithoutCancel(r.Context())` so a dropped connection cannot leave a pin, a pairing or a deposit half-written with no audit row; the idempotent ones (`handleSetSchedule`, `handleUnpair`) stay on the request context. Their routes are registered as `s.tracked(s.requireAdmin(s.handleX))`, so the `detached` counter is incremented the moment `ServeHTTP` dispatches -- before `requireAdmin`'s session lookup, which is itself a store round-trip that `ReadTimeout` (15s) lets outlast `shutdownTimeout` (5s). Registering inside the handler was too late: `Shutdown` returns after its timeout with requests still active, and one still in the auth lookup would leave `WaitDetached()` reading zero and the store closing under a request about to pin a key. The header-read window before `ServeHTTP` is entered cannot be covered by any counter, because no handler goroutine exists yet; `Shutdown`'s own drain is what covers it. The counter is a mutex and a `sync.Cond`, not a `sync.WaitGroup`, which panics when an `Add` from zero races an in-progress `Wait` -- two admin requests at SIGTERM do exactly that. `WaitDetached()` is what `cmd/server` blocks on before closing the store, because `http.Server.Shutdown` returns without knowing these goroutines exist.
- Audit actions: `backup.paired`, `backup.pair_failed`, `admin.backup_run` (details start with `outcome="success|failure"`), `admin.backup_unpair`, `admin.backup_key_pin`, `admin.backup_schedule`, `admin.backup_export` (a downloaded capsule, resource the capsule ID). `AuditDetails` flattens the lib's details map into the bounded audit field with locally derived fields first and remote error text last; values are quoted and `=` is escaped before the final `AuditSafe` cut. `cmd/server` uses it for the scheduler and CLI rows. Details carry key or capsule IDs, digests and paths, never the token.
- Rate-limit keys for `login:`, `mfa:` and `sso:` come from `auth.ClientIP`, never from `RemoteAddr` or a raw header, so a limit is neither shared by everyone behind a proxy nor bypassable by forging `X-Forwarded-For`.
- CORS permits only the exact configured `KY_APP_URL` origin and credentialed browser writes require matching CSRF cookie/header tokens.
- API request bodies are capped at 1 MiB and all responses receive baseline CSP, anti-framing, MIME-sniffing, and referrer-policy headers.
- `GET /api/settings` tiers its payload: public fields for the login screen, `db_driver`/`scim_enabled=false` for any session, and `extra_settings` for admins only; KyRecovery tokens are omitted in both sealed and legacy plaintext forms, dropped by the `kyrecovery_token` key prefix rather than by literal key name. SSO and retired SCIM settings are also omitted by `sso_`/`scim_` prefixes; public `sso_providers` exposes only ID, name and relative login URL.

- SSO callbacks and the directory webhook only touch global accounts; none of them, and no global group, can select or grant a tenant. Tenant membership is granted only through the authorized `/members` routes.
- Tenant namespace is `/api/organizations/{organization}`: GET organization; GET/POST `/environments`; GET/PATCH/DELETE `/environments/{environment}`; GET `/audit` or `/environments/{environment}/audit`; GET `/members`; PUT/DELETE `/members/{user}`. Unknown tenant paths/methods return JSON 404, never SPA content.
- Endpoints: `POST /environments/{environment}/enrollment-tokens` (`{runtime}`; 201 with the one-time token and the Docker-socket disclosure; the generated command passes a one-use HTTPS enrollment link to the persistent agent; the response explains fingerprint approval and root-equivalent Docker authority); `GET /endpoints`, `GET /environments/{environment}/endpoints`, `GET|PATCH /endpoints/{endpoint}`, `POST /endpoints/{endpoint}/approve` (`{fingerprint}`, 64 hex, must be the enrolled key), `/reject`, `/revoke`. Deleting an environment with a non-revoked endpoint returns `409 environment_in_use`.
- `GET /api/agent/v1/connect` is the agent WebSocket (`agent_connect.go`). Handshake: server sends a 32-byte nonce, its instance fingerprint and supported versions; the agent answers with its endpoint ID, version and a signature under the connection context; the key is looked up by state (pending endpoints authenticate with their key under review), and wrong key, unknown, revoked and expired all close with `identity_revoked` while a wrong version closes with `incompatible_version`. Infrastructure failures during handshake or per-frame identity/state checks close with retryable `protocol_error`; only authorization failures report revoked/retired/pending identity. One socket per endpoint (`duplicate_connection` otherwise). Pending sockets may heartbeat and receive `enrollment.approved`; others heartbeat (`last_seen_at`), send inventory (generation must rise; first accepted snapshot moves approved or offline to active) and get `error unsupported_type` for anything else. Every frame re-reads the endpoint state so revocation cannot be outrun. Three missed heartbeats (90 s) or a disconnect mark an active endpoint offline. Approval notifies the live socket; reject and revoke close it in the same request; `BeginShutdown` closes every agent socket with `server_shutdown` because hijacked connections are invisible to `http.Server.Shutdown`. Connection outcomes are audited as `agent.connect` in organization scope; unknown endpoints produce no row. Per-IP limit 20/minute; the read limit is 4 KiB until the handshake succeeds and 4 MiB after. The auth frame names its key's fingerprint: a retired key closes with `key_retired`, a key still under review with `key_pending_review`, and a revoked or expired endpoint with `identity_revoked` whatever the key. `inventory` frames carry a full `protocol.Snapshot`; a frame over `protocol.MaxSnapshotBytes` (1 MiB) is answered with an `error snapshot_too_large` frame and the session continues; an accepted frame is decoded with `protocol.UnmarshalSnapshotBounded`, which stops appending past each list cap while decoding so a byte-capped payload of tiny elements cannot expand into tens of megabytes before the caps apply, and then clamped to the declared schema (`protocol.Clamp`: list caps, string bounds, label caps, text safety) and stored as its re-encoding, never as the agent's bytes; a generation the store refuses (not newer, or more than an hour ahead of the server clock) is answered with `error generation_rejected` on every rejection, while the high-severity `generation_rejected` event is raised once per session and stands once per endpoint until acknowledged; `GET /endpoints/{endpoint}/inventory` (`endpoint.read`) returns it with `observed_at`, `received_at` and the endpoint state so the UI can show staleness and clock skew, `404` until the first report. Under retention pressure telemetry backs off before anything else: metrics are refused with `error retention_pressure` at `degraded`, inventory as well at `stopped`, the session and its heartbeats continue, and endpoint state and audit are never refused. `metrics` frames are validated before storage, bounded to 1000 samples, cadence-dropped per session and per container, and observations more than five minutes from the server clock are re-stamped with server time. Each sample carries the container's cumulative `restart_count`, so a rising series is a container restarting; -1 means the runtime did not answer and the UI shows nothing rather than claiming zero; capacity exhaustion returns `error samples_budget_exhausted` while keeping the socket alive, whereas malformed metrics close it. `GET /endpoints/{endpoint}/samples` returns the newest sample per container within the six-hour retention, `GET /endpoints/{endpoint}/containers/{container}/samples?minutes=N` one container's raw series (window capped at six hours, 400 rows), and `GET /endpoints/{endpoint}/containers/{container}/rollups?hours=N` its hourly summaries (capped at seven days, 200 rows). All three are `endpoint.read`. The summary is a separate route rather than a wider window on the raw one, so a caller always knows which resolution it asked for and got. `hello` records capabilities once per session (a second hello is ignored); its payload is decoded with `protocol.UnmarshalHelloBounded` (64 entries, 4 KiB of text) and every non-inventory frame payload is capped at 64 KiB (`maxControlPayload`). When a socket ends (`markOffline`), its registry slot is freed first so a reconnecting agent never reads as its own duplicate, and the offline write is skipped when a successor already holds the endpoint, on a detached context bounded to ten seconds. Before a second socket is called a duplicate the incumbent is pinged with a three-second deadline; a socket the network dropped silently (no FIN, the agent redials before the server's read timeout) is evicted and the newcomer admitted with no event; the eviction is audited as `agent.connect` with result `failure` against the evicted socket's address, details `evicted: unanswering socket displaced by <ip>`. A frame delivered within the ten-second handler budget counts as proof of life, because the reader cannot answer a ping while it hands a frame to the loop, so a busy incumbent is never evicted. Only a live incumbent yields a `duplicate_connection` event, which names both the refused address and the address holding the live socket, because the holder is the party to doubt. Every frame re-checks the session's own key as well as the endpoint state, and acknowledging a rotation closes the retired key's live socket with `key_retired` in the same request. `identity.rotate` (new public key plus the current key's signature under the rotation context) is answered with `identity.rotate {fingerprint, code}` where `code` is empty on success or `rotation_pending`, `rotation_blocked` (an unacknowledged `duplicate_connection` event stands) or `rotation_refused`. A duplicate connection records a high-severity `duplicate_connection` event. `POST /endpoints/{endpoint}/keys/{fingerprint}/acknowledge` (`endpoint.enroll`) makes the pending key the only approved key and pushes `identity.rotated` to a live socket; `POST /endpoints/{endpoint}/events/{event}/acknowledge` clears an alert. Endpoint JSON carries `pending_fingerprint`, `capabilities` and up to ten unacknowledged high-severity `alerts`.
- `GET /endpoints/{endpoint}/containers/{container}/removal` (`endpoint.read`) previews what destroying a container would mean, answered from the stored inventory with its age rather than by asking the agent: a preview must not be a way to make an endpoint do work, and the command re-checks the state when it acts. It names what survives as well as what goes, because an operator who thinks the data is going hesitates over the wrong thing and one who thinks it is safe when it is not loses it.
- `POST /endpoints/{endpoint}/commands` dispatches one container action with an optional `expects` block naming the image digest and state the actor saw. `container.start`, `container.stop` and `container.restart` need `container.operate`; `image.pull` needs `image.pull` and must name a tag or a digest — a bare repository name means every tag in it to a runtime — and `image.remove` needs `image.destroy`; an image action names `reference` instead of `container`, and a request naming both is `400`. Each is validated against its own grammar so neither accepts the other's abuses: a reference must satisfy `protocol.ValidImageReference`, where every component starts and ends alphanumeric, which rejects `..`, `.` and empty components by construction; the agent checks the same function before building a path. `container.remove` needs `container.destroy`, which the matrix gives to administrators only, and additionally requires an `expects.state` and a `confirm` matching the container's name **as the server last observed it**, not as the request repeats it; the dispatched frame then names the container ID that confirmation resolved to, so a name reassigned between inventory and execution cannot redirect a removal. `image.remove` is destructive in the same way and earns the same ceremony: `confirm` must match the reference as the last inventory reported it, the reference is dispatched (Docker untags a tag and deletes an ID, so substituting the ID would widen what was confirmed), and the server pins `expects.image_digest` to the image that reference stood for, which the agent re-reads before deleting. A caller-supplied `expects` on an image action is `400` rather than silently overwritten. Destructiveness follows the permission set — `container.destroy` and `image.destroy` — rather than a second list, so a future action given either inherits the ceremony. The record is written before the frame is sent, so a command that reaches the agent and loses its answer is still accounted for. An endpoint that is not connected is `409` and writes no record at all: queueing would mean an operator's decision executing later against a host they have not seen since. A frame that cannot be queued settles the record as `failed` in the same request. Neither the actor nor the confirmation reaches the agent. `GET .../commands` and `GET .../commands/{command}` are `endpoint.read`.
- `GET /endpoints/{endpoint}/containers/{container}/logs` streams one container's log as text, or as `text/event-stream` with `follow=1`, or as a named attachment with `download=1`. It needs `container.logs`, which the matrix gives to everyone but the read-only member, and which is one of the few successful reads that writes an audit row: a log carries whatever the application printed. The identifier is resolved against the last inventory and the **container ID** is what the endpoint is asked for, so a name reassigned by a recreate cannot redirect a stream. Bounds are explicit and reported when they bite: `tail` (default 200, max 10,000), `since` as an age or an RFC 3339 instant, `search` as a plain substring matched here, 10,000 lines or 4 MiB per request counted over every line read, 1 MiB buffered per stream, and two streams per endpoint (`429` past that). A gap is a notice naming the bytes dropped, never a silent join; every line the control plane writes is marked as its own, so nothing it says can be mistaken for something the container printed. The reader disconnecting sends `log.cancel`, so the endpoint stops reading the host rather than running on for nobody. Two more things make the shape honest. Every line the control plane writes carries a token minted for the request and returned in `X-KyYard-Notice-Token`, because a container can print a line that looks like a notice but cannot know a token it never sees; and a bare carriage return ends a line, as the event-stream grammar says, so container output cannot escape its `data:` field and introduce events of its own. The response sets a write deadline of its own (`http.NewResponseController`), sized to the request's budget and refreshed on each write: the server's `WriteTimeout` is an absolute deadline for a whole response and would otherwise sever a stream mid-log with none of the promised markers. Authorization is re-asked every 25 seconds -- session and membership both -- and a membership change closes that reader's streams in the request that commits it. An oversized chunk ends that one stream rather than the session: the socket carries heartbeats, inventory and every command, so answering a data frame by closing it would turn an agent-side slip into an endpoint nobody can manage. Every socket transition closes the endpoint's readers exactly once: at the moment of displacement, because the successor has never heard of a stream the predecessor was serving and nothing would ever arrive on it again, and otherwise when the last live socket goes. The loser's unwind does not do it, or a successor's own readers would go with them.

- A `result` frame settles its command once, scoped to the endpoint that answers, so a late duplicate or an answer for someone else's command changes nothing. When a session ends, everything dispatched and unanswered becomes `unknown` with the reason: the connection going is not evidence the work did not happen, and nothing is retried on its own. A snapshot whose generation is not newer is logged and ignored.
- `POST /api/agent/v1/enroll` is the agent-facing enrollment route: no session, no CSRF (no cookie), strict JSON `{token, public_key, proof, name, facts}` in base64url, per-IP limit 10/minute, `201 {endpoint_id, state, fingerprint, instance_fingerprint}`, `409 name_taken`, and every other refusal a uniform `401 Enrollment refused`. Unknown `/api/agent/` paths return JSON 404.
- `GET /api/organizations` lists the session user's own active memberships (`id`, `name`, `role`) for the organization selector. It is identity-scoped, not tenant-scoped: it never lists another user's organizations and platform administrators without membership get an empty list.
- Membership writes take `{role, status?}` (status defaults to `active`); the user ID comes from the path and must already exist (404 otherwise). `409 {code: last_administrator}` means the change would leave the organization without an active administrator, including an administrator demoting, disabling or removing themself.
- `tenantRoute` authenticates unrestricted sessions, derives actor and correlation ID server-side, and sends `X-Request-ID` plus `Cache-Control: no-store`. Handlers pass explicit URL scope to authorized store methods; clients cannot supply actor, organization or arbitrary update fields in JSON. Existing Origin/CSRF/body limits apply.
- Every tenant JSON body goes through `strictJSON` (unknown fields and trailing documents rejected). Environment create/update accepts only `{name}`; lists accept nonnegative `offset` and `limit` 1–200 (default 50). Store errors map to generic 400/403/404/409/500 responses. Request parsing/authentication/CSRF failures occur before the transactional tenant audit path.
