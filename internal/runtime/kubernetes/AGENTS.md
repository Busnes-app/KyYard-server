# Kubernetes runtime adapter

## Purpose
Reads the cluster a KyYard agent runs in, as its ServiceAccount, and returns product types only. It reads inventory, health input, pod logs and one Deployment's status for health validation and, in the namespaces its manifest grants, applies and removes an application's objects, restarts, scales and deletes workloads and pods, reads and applies a workload's pod template, and opens pod terminals.

## Ownership
Owns the client-go typed clientset (`New`, `InCluster`, `NewFromClientset` for the fake clientset), the mapping into `protocol.KubernetesInventory`, pod log streaming, and the agent identity Secret (`SecretIdentityStore`). The `render/` subpackage turns a cluster deployment frame into client-go objects; only this package imports it. No client-go type leaves this package; `cmd/agent` sees only `Client` (with `Deploy`, `Remove`, `Inspect`, `Operate`, `ReadWorkload`, `ApplyWorkload` and `OpenExec`), `SecretIdentityStore`, `OwnNamespace` and `ErrIdentityConflict`.

## Local Contracts
- Static Service IPs (docs/application-schema.md and docs/agent-protocol.md, Static Service IPs): render the requested `ClusterIP`, reject a changed existing IP before writes and on conflict retries, and allocate/update the Service before that service's claims/configuration/Deployment. The actual Kubernetes create validates range and availability; dry-run does not reliably reject allocated addresses. Allocator refusal is `service_ip_unavailable`; existing-address mismatch is `service_ip_immutable`, with `Service/<name>`. Updates preserve assigned addresses and IP families. Inventory includes instance/service ownership labels for backend URLs. `TestStaticServiceIPCreateAndPreserve` and `TestStaticServiceIPRefusalsBeforeWorkloadWrites` cover preservation and retries; `TestManifestOnARealCluster` proves real allocator refusal and a pinned address across reapply.
- `Snapshot` lists nodes, namespaces, deployments, statefulsets, daemonsets, pods, services, persistentvolumeclaims and storageclasses (`StorageClasses`: name, default when the `storageclass.kubernetes.io/is-default-class` or its beta annotation is `true`, sorted by name) with `List` (`Limit` 500, `Continue` paging, stopping once past the cap), all at once and alongside the server version (`serverVersion`, the one `ServerVersionWithContext` call `Facts` also uses), so the snapshot costs the slowest list, not the sum; sorts each list by namespace then name, and leaves the cut and the byte fit to `protocol.Clamp`/`Shrink`. A list that fails is reported empty and named in `Truncated` with a log line; `Snapshot` never returns an error. `Engine` is `Runtime: kubernetes`, the API server's `GitVersion`, `Major.Minor`, and `Platform` split into OS and arch.
- Node `Ready` is the `Ready` condition; roles are the `node-role.kubernetes.io/<role>` label keys. A workload's `Desired` is `spec.replicas` (unset is 1) or, for a DaemonSet, `status.desiredNumberScheduled`. A pod's owner is its controller, except that a ReplicaSet named `<deployment>-<pod-template-hash>` is reported as that Deployment: the role cannot read ReplicaSets. A pod carries its UID. Container `State` is `running`, `terminated` or `waiting` (also when no status exists yet), `Reason` the waiting or terminated reason. Service ports read `port[:nodePort]/PROTOCOL`.
- `Logs` validates `LogRequest.ValidateFor(kubernetes)`, reads the pod (`get pods`), takes the only container when none is named and refuses otherwise with `unknown_container: ...`, and streams `GetLogs(...).Stream` with `TailLines`, `SinceTime`, `Timestamps`, `Follow` and `LimitBytes` 4 MiB; it stops at `protocol.MaxLogLines` or `MaxLogBytes`, closes the stream when the context ends, and reports fixed error texts, never API error bodies. History has 60 seconds, a follow an hour.
- `SecretIdentityStore` keeps the identity JSON under key `identity.json` in an Opaque Secret in the agent's own namespace, labelled like the manifest's objects. `Save` updates against the `resourceVersion` of the Secret as last loaded or saved, creating only when it was absent. A conflict (or a lost create race) re-reads once: a Secret holding another endpoint's identity or a higher `Generation` is `ErrIdentityConflict` and is never overwritten, otherwise the write is retried once and a second conflict is `ErrIdentityConflict`. A second agent sharing the identity therefore stops (`cmd/agent` exits and the restarted pod reloads) instead of rolling the generation back. Two writers at the same `Generation` are not a rollback and are let through; only the connected agent raises it, and the server's `duplicate_connection` refusal keeps one connected. A Secret deleted under a running pod is not re-created: later saves log and fail until the pod restarts, which is the operator's re-enrollment path.
- `manifest/` renders the install manifest with `text/template` and JSON-quoted scalars and imports no `k8s.io` package, so the server that renders it links no client-go. `Render` refuses an unpinned image (`config.IsPinnedAgentImage`), an empty name and a non-HTTPS link; `FileName` reduces the name to `kyyard-agent-<slug>.yaml`. The objects, RBAC and pod settings are the spec's; the pod also runs as UID/GID/fsGroup 65532 (the image's default user is root) and mounts the enrollment Secret read-only with mode 0440, `optional: true`, and an `emptyDir` `scratch` at `/var/lib/kyyard-agent` (the root filesystem is read-only; `cmd/agent --scratch-dir`, that path by default, is the cluster agent's `CommandDir` for its command and deployment ledgers, while identity stays in the Secret). `Input.Namespaces` (sorted, distinct DNS labels, at most 32) adds, per namespace, a Role and RoleBinding `kyyard-agent-deploy` to the agent's ServiceAccount: `apps deployments` and core `services`, `configmaps` get/list/create/update/patch/delete, core `secrets` get/create/update/patch/delete and no list, `apps statefulsets`, `daemonsets` get/list/patch/update/delete, core `pods` delete and `pods/exec` create. The ClusterRole's read rules are unchanged and it gains one `authorization.k8s.io selfsubjectaccessreviews create` rule. `RenderRBAC(name, image, namespaces)` renders the same file without the enrollment Secret (no link) but with the same agent Deployment on `image`, for an administrator changing an enrolled cluster's namespaces or upgrading its agent in place; both refuse an unpinned image; a namespace dropped later keeps its Role until deleted by hand, as the header says. The deploy Role also grants `persistentvolumeclaims` `get, list, create` (never `update`, `patch` or `delete`: a claim KyYard created stays until the operator deletes it), and the read ClusterRole `storage.k8s.io` `storageclasses` `get, list`; an agent under an older manifest reports `storage_classes` truncated and its claim creates are refused `forbidden` until the regenerated manifest is applied.
- `render.Request` renders each service of a validated cluster frame as a `Set`: ConfigMap `<name>-env` (the env keys not in `SecretKeys`), Secret `<name>-secret` (`Opaque`, the secret keys; nil without any), Deployment `<name>` (one replica, `Recreate`, selector `kyyard.busnes.app/instance` + `/service`, one container named after the service with `_` as `-`, image `Pull.Reference`, container ports deduplicated, `envFrom` the ConfigMap then the Secret, `restartPolicy: Always`, `automountServiceAccountToken: false`, no probes, resources or security context) and Service `<name>` (`ClusterIP`, same selector, one port per published port named `<protocol>-<port>`, `targetPort` the target; nil without ports), names from `protocol.KubernetesNames`. Every object carries the six labels (`app.kubernetes.io/name`, `/instance`, `/managed-by: kyyard`, `kyyard.busnes.app/application`, `/instance`, `/service`) and the annotations `kyyard.busnes.app/revision`, `/deployment`, `/spec-digest`; the pod template carries the labels and the deployment annotation, so every apply rolls the pods.
- `Deploy` validates `ValidateFor(kubernetes)`, then runs every service's precondition before any write: the first also asks the API server (`SelfSubjectAccessReview`, `create` `apps/deployments` in the namespace) and stops `denied forbidden` without the grant, then reads the namespace and stops `denied pod_security` (detail `missing`, `privileged` or `invalid`) unless `pod-security.kubernetes.io/enforce` is `baseline` or `restricted`; each reads its planned objects by name and stops `denied name_taken` with `Kind/name` when one exists without this instance's `kyyard.busnes.app/instance` label. `started` is called once, before the first write. Per service, `create` writes Service, missing claims, ConfigMap, Secret and Deployment in that order, updating an owned object at its `resourceVersion` (a Service keeps its cluster IPs and IP families) and creating an absent one; a conflict, a lost create race or an update whose object vanished re-reads once (still owned: written again; gone: created; now foreign: `name_taken`), and a second conflict fails `conflict` with `Kind/name`; any other 403 on a write asks a `SelfSubjectAccessReview` for that verb, resource and name: not granted (an older or edited manifest) is `denied forbidden`, granted is the cluster refusing the object (quota, admission policy): `denied admission_denied` with `Kind/name`; a review the API server could not itself answer is classified as a failed call, never `admission_denied`. A service with no secret-backed key or no published port has its owned `<name>-secret` or Service from an earlier revision deleted at the UID read (gone or replaced counts as done; a foreign one is left alone). The Deployment as written is the service's identity (UID, generation, the pulled digest). `start` reads the Deployment every `rolloutPoll` (2 s) until the observed generation is current and the one replica is updated, ready and available (render sets `minReadySeconds` 10 and `progressDeadlineSeconds` 540, below the ten-minute apply deadline), within the request deadline. For the current generation `ReplicaFailure=True` or Progressing `ProgressDeadlineExceeded` on two consecutive polls ends the wait as `failed rollout_timeout`; a transient read failure (no answer, 429, 5xx) is not an answer (the wait keeps the last good read and polls on), while any other read error ends the wait with its code; past the deadline it is `timed_out rollout_timeout` with the last good read's reasons. The detail carries the Progressing reason, the Available reason when unavailable, the ReplicaFailure reason, `claim=Pending` or `claim=Lost` for each of the service's planned claims in that phase (read by name past the deadline; a Bound claim or a failed read adds nothing) and the newest labelled pod's waiting reason (at most three, in that order), words only; nothing is rolled back and every later step is skipped. Other API errors map to `forbidden` (403 on a read), `runtime_status` with the code, `runtime_timeout`, `cancelled` (unknown) or `runtime_error`.
- `Remove` validates `ValidateFor(kubernetes)`; the first service's precondition lists Deployments, Services and ConfigMaps in the namespace by the instance label, keeping only labelled ones, and services found by label but not named are added. Each Deployment's Secret is read (get, never list: the role grants no Secret `list`) by that Deployment's own name, `<deployment>-secret` (and each labelled `<X>-env` ConfigMap's `<X>-secret`, for a service whose Deployment was never created), which stays stable across a removal naming any subset of services; a named service whose Deployment is already gone falls back to the name `KubernetesNames` would compute from this request's own services, which is unstable across a collision (two service names sanitising to the same slug) but only matters once the Deployment carrying the stable name is gone too. Each delete carries the UID read at the precondition as a `Preconditions`, so an object recreated under the same name after the read is not the one removed; a resulting conflict is treated like the object already being gone rather than a run failure. Each service's `remove` deletes its objects with foreground propagation (already gone counts as removed) and is skipped when nothing of it is left. `Snapshot` reports a Deployment's `kyyard.busnes.app/application` and `/instance` labels in `Workload.Application`/`Instance`.
- `Deploy`'s per-service `create` also drops a stale Secret: when the render carries no Secret (no secret-backed keys this apply) but an owned `<name>-secret` remains from an earlier revision, it is deleted so a removed key's value does not outlive it; a Secret under that name that is not this instance's is left untouched, since nothing in this apply writes to it.
- `Inspect` validates `InspectionTarget.ValidateFor(kubernetes)` and, within `callBudget`, gets the target Deployment (not found answers `WorkloadStatus{Missing: true}`; one recreated under the name answers with its own UID, which the server judges `changed`) and lists its pods by the Deployment's `spec.selector` (immutable, unlike its labels; a Deployment without one, or with an empty one, is an error) (`Limit` `MaxWorkloadPods`+1). More than `MaxWorkloadPods` pods, or a list that continues, is an error the agent sends as `unavailable`, never a cut list: one omitting every baseline pod would read as a recreate, and one omitting a restarted pod would hide its restarts. The status carries the Deployment's UID, generation, observed generation, desired (`spec.replicas`, unset 1), updated, ready and available counts and at most `MaxWorkloadConditions` conditions (type, status, reason word; messages never); each pod its name, UID, phase and containers as `pod` maps them, with image and image ID cleared and a reason that is not one word dropped. It uses only `get deployments` and `list pods`, which the ClusterRole already grants.
- Workloads (`workloads.go`): the wire vocabulary (actions, steps, fixed detail words, the managed rule) is docs/agent-protocol.md, Kubernetes runtime; this package owns how it is carried out. `Operate` matches `client.Options.Operate` and refuses a bad action, reference, kind pairing or replica count before any call. A `SelfSubjectAccessReview` for the verb on the named object is the boundary (the granted namespace list is the server's check). Restart and scale are JSON merge patches; scale carries the read's `metadata.resourceVersion` (a concurrent change is `conflict`) and refuses `pvc_retention` before any write for a StatefulSet scaled below its current replicas whose `persistentVolumeClaimRetentionPolicy.whenScaled` is `Delete` (the handle's `claimsDeletedOnScale`); delete re-reads the object and deletes at its UID with `Background` propagation, refusing a `managed-by: kyyard` object for `workload.delete` (`application_managed`). API error text never leaves; calls are bounded by `callBudget` and the command's deadline.
- `ReadWorkload` takes an object-shaped `InspectionTarget.Workload` (Deployment, StatefulSet or DaemonSet; a pod or the UID shape is an error) and returns a `WorkloadConfiguration` that passes its own `Validate`: containers and init containers (at most `MaxWorkloadContainers` each), env literals and Secret/ConfigMap keys by `<name>/<key>` (Secrets are never read), distinct `envFrom` names, cpu and memory requests and limits, replicas (unset 1; nil for a DaemonSet), paused, strategy, `resourceVersion`, and `Managed` when `app.kubernetes.io/managed-by` is `kyyard`. `ImageID` is left empty. `Unsupported` names only what an apply would drop: `env_field_ref` (any other env source) and `env_truncated`/`argv_truncated` (entries past the protocol's bounds, duplicate names). Extra containers, extra `envFrom` and extended resources are not shown but never touched, so `containers_truncated`, `env_from_truncated` and `resources_extended` are not emitted.
- `ApplyWorkload` validates the frame (`denied invalid_request`) and runs `precondition` (review for `patch`, then `podSecurity` as `Deploy` does, then a fresh read and its refusals), `apply` and `rollout`, all `denied` before any write. `edit` sets only the form's fields where they differ from the read (an env entry mapping to the same thing is reused verbatim, so a Secret ref keeps `optional`); `handle.write` diffs the edited object against the bytes read (`strategicpatch.CreateTwoWayMergePatch` with the typed object), adds `metadata.resourceVersion` from the read and sends a strategic merge patch, so fields the bundled types do not know are never sent and survive. `started` is called before the write.
- Exec (`exec.go`, protocol §7 and Kubernetes runtime, Pod exec): `OpenExec` re-reads the pod within `callBudget` (fixed texts for gone, another UID, not `Running`, container not in `spec.containers`), then `execAllowed` refuses a namespace without Pod Security `baseline`/`restricted`, then a pod that `baselineViolation` finds breaking a baseline control (every container kind; the detail word wraps `protocol.ErrExecPodSecurity` and never reaches the wire), both `protocol.ErrExecPodSecurity`, and only then a denied `create pods/exec` review (`protocol.ErrExecForbidden`); these two errors are the only ones `internal/agent/client` forwards as a close reason. Only a client from `New`/`InCluster` can exec (SPDY, redirects refused); `NewFromClientset` answers `ErrExecUnavailable`. The attachment is established after `OpenExec` returns, so a failed upgrade shows as a failed first read. Stdin and stdout are `io.Pipe`s, `Resize` keeps only the newest pending size, input and resize reset the idle deadline (output does not), `Close` is idempotent and unblocks Read and Write. `Inspect` carries exit 0 for a nil stream result and an `exec.ExitError`'s code, unless the session cancelled the stream itself, when the exit is unknown.
- Claims: `render.Request` gives a service mounting claims one `PersistentVolumeClaim` per claim in `Set.Claims` (labels and annotations like its other objects, `ReadWriteOnce`, the requested size, `storageClassName` only when the plan names one) and a pod volume named after the claim with the service's mounts. `Deploy`'s precondition reads each claim: another owner's is `name_taken` and this instance's with another class (when the plan names one), size or access mode is `claim_immutable`, both with detail `PersistentVolumeClaim/<name>` and before any write; `create` creates a missing claim after the Service and before the ConfigMap and never updates one (one that appeared since must pass the same check). `Remove` never deletes a claim: it pages the instance's claims by label, like the inventory lists, and reports each as a skipped `volume` step with detail `retained` under the service label that mounts it; past `MaxDeploymentVolumes` emitted steps the rest are left off and logged, not failed, since the cluster still holds them.

## Verification
- `go test -race ./internal/runtime/kubernetes/...` runs against `k8s.io/client-go/kubernetes/fake` (mapping of every field, owner resolution, caps, a forbidden list, paging, concurrent lists over an HTTP API server, facts, log options, container refusal, follow cancellation, the line ceiling, Secret create/update/conflict, a stale second writer).
- `go test -race ./internal/runtime/kubernetes/` also drives `Deploy` and `Remove` against the fake clientset with reactors standing in for the API server (access review, UIDs and generations, rollout status, conflicts, a UID-precondition conflict on delete): create then update in place, an identical re-apply, a transient read, a 403 or 404 read and a parent cancel during the rollout, a lost race re-read (foreign: `name_taken`), an update of a vanished object, a write 403 told apart by access review, a stale Secret dropped when its keys go and a foreign one left alone, refusals before any write, one conflict retried, a timed-out rollout's reasons, a Docker frame refused, removal by label that leaves foreign objects and never lists Secrets, a Secret found by its Deployment's name across a naming collision, a recreated same-name object surviving a guarded delete, an unbound claim named in a timeout, a claim read error that is not `name_taken`, a claim list error that deletes nothing, and the claim cap on removal; `TestSnapshotSurvivesAForbiddenStorageClassList` pins `storage_classes` in `Truncated`.
- `go test -race ./internal/runtime/kubernetes/ -run 'Operate|Workload'` drives `Operate`, `ReadWorkload` and `ApplyWorkload` against the fake clientset with access-review reactors: each action per kind, forbidden, DaemonSet scale and replica bounds, the `pvc_retention` refusal and the scale patch's resourceVersion, the delete UID precondition and a replaced object, refs read without Secret values, a field-ref env as unsupported, apply conflicts (version and API 409), managed, unsupported and Pod Security refusals, a managed delete refused, untouched fields (labels, annotations, volumes, probes, security contexts, envFrom, extended resources, a ref's `optional`) byte-identical, the exact strategic merge patch and unknown raw fields surviving it (`TestApplyWorkloadPatchesOnlyTheEdit`), an unchanged apply writing the same spec, a timed-out rollout and a skipped one. The Deployment patch reactor applies the strategic merge patch and enforces `metadata.resourceVersion`.
- `go test -race ./internal/runtime/kubernetes/ -run PodExec` drives `OpenExec` through an injected `streamer`: echo, exit code 3, nil as exit 0, nil after Close as unknown, resize reaching the queue, Close unblocking Read and Write (and an exit status after our cancel not believed), a transport error without exit code, idle and lifetime deadlines, input resetting idle, the refusals, and the Pod Security and access-review gates (`TestPodExecGates`), each baseline control (`TestBaselineViolation`) and a privileged pod in a baseline namespace refused before the review (`TestPodExecRefusesANonBaselinePod`). `KY_TEST_KUBECONFIG=... KY_TEST_EXEC_IMAGE=<digest-pinned image with sh> go test -run TestPodExecOnARealCluster ./internal/runtime/kubernetes/` creates namespace `kyyard-test-exec` with one pod, runs `sh -c 'echo hi; exit 3'` as the kubeconfig's user and asserts the output and exit code 3; not in CI.
- `go test ./internal/runtime/kubernetes/manifest/` decodes every rendered document strictly into client-go types and asserts the RBAC (the ClusterRole get/list only, no secrets, configmaps, watch or wildcard; the only Secret access is the namespaced identity Role; each deploy Role's workload, pod `delete` and `pods/exec` rules), the pinned image, the token appearing once inside the Secret, and the pod's settings, the scratch volume included; `TestManifestRegenerated` asserts the regenerated file carries the identical Deployment and no Secret or link.
- `KY_TEST_KUBECONFIG=<kubeconfig of a disposable cluster> KY_TEST_DEPLOY_IMAGE=<digest-pinned image that keeps running, e.g. registry.k8s.io/pause@sha256:...> go test -run TestManifestOnARealCluster ./internal/runtime/kubernetes/` creates the namespace `kyyard-test-deploy`, applies the manifest granting it, impersonates the ServiceAccount (SelfSubjectAccessReview: `get secrets` denied cluster-wide, `list pods` allowed, identity Secret update allowed only by name; in the granted namespace `create deployments`, `patch deployments`, `delete pods`, `create pods/exec`, `delete services`, `update configmaps` and `get secrets` allowed, `list secrets` denied; `create deployments`, `patch deployments`, `delete pods` and `create pods/exec` in `default` denied), round-trips the identity Secret, takes a snapshot naming the nodes, deploys one service as the agent and sees it ready with the reported UID, removes it and sees its Deployment, ConfigMap and Secret gone. It creates and deletes cluster-scoped RBAC and both namespaces before and after; it skips without `KY_TEST_KUBECONFIG`, fails without `KY_TEST_DEPLOY_IMAGE`, and is not in CI. The run also creates a claim of the default StorageClass mounted by the pod, applies twice, reads the settled Deployment with `Inspect` (available, its one pod running), and proves the removal keeps the claim.
- `go test ./internal/runtime/kubernetes/render/` compares a two-service render with the expected objects field by field, decodes each strictly through the client-go scheme, and checks every name and label against apimachinery's validation for awkward projects and services.
