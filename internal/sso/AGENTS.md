# SSO

## Purpose
Provides unified Single Sign-On federation for KySignOn, Generic OpenID Connect (Google, Microsoft Entra ID, Okta, Keycloak), and SAML 2.0 Service Provider (SP).

## Ownership
Owns the application adapters around OAuth/OIDC login, KySignOn HMAC-SHA256 signed directory sync webhooks, and SAML metadata publication.

## Local Contracts
- The private bounded JWKS transport checks all RSA moduli at 2048 bits using verifier-matched envelope/case-sensitive member parsing. All OIDC adapters, including configured/installer providers, share it. Preserve upstream signatures/claims/nonce/key handling, local linking and tenant/app-role checks. `GODEBUG=fips140=on` additionally requires HTTPS legacy issuers and refuses discovery/token redirects; existing HTTPS endpoint and configured-provider policies remain intact. Legacy directory HMAC inputs require `crypto.MinHMACKeyBytes` at signature use.
- Verified OIDC ID-token claims carry `Issuer` and `AppRoles`, read only from KyIdentity's `roles` claim (a string array; any other non-null type rejects the token; `app_roles` is not read); OAuth profile responses cannot supply those verified claims. Managed `kyidentity` sign-in requires explicit exact issuer/subject assignment and the `kyyard.admin` app claim for installer administrators; global roles do not grant it. Provider projections label installer management without returning credentials.
- Explicit local-account links use verified provider subjects and preserve local account ownership; KySignOn directory webhooks refuse to update, deactivate or delete a linked local account.
- `Provider` supports OIDC discovery (KyIdentity included) and OAuth 2 authorization-code providers with a JSON profile API. OAuth profile mappings use dot paths; subjects accept strings or exact JSON numbers and must be stable IDs. No account linking by email or automatic tenant grants.
- UI-configured endpoints require HTTPS with certificate verification. They are administrator-trusted identity infrastructure (private KyIdentity hosts allowed). HTTPS discovery cannot downgrade authorization, token or signing-key endpoints to HTTP. Network calls have deadlines, redirects are refused, profile bodies are capped at 1 MiB, and credentials stay server-side. PKCE S256 is required; provider-specific nonstandard grants/profile formats are not claimed as supported.
- `KySignOnClient.HandleSyncWebhook` verifies HMAC-SHA256 signatures before modifying local user state.
- `HandleSyncWebhook` refuses a `user.created` whose username matches an existing account ignoring case with `ErrUsernameTaken` (named in the error), never linking to or duplicating that account; a racing create is caught by `idx_users_username_lower` the same way. A `user.updated` renaming onto a taken username is the same `ErrUsernameTaken` (from `DirectoryTx.UpdateUserIdentity`'s `ErrAlreadyExists`), so driver text never reaches the caller. Every `ErrUsernameTaken` writes, after the event's transaction rolls back, one audit row `auth.sso.refused` (result `denied`, resource `kysignon`, details `username=` plus the name through `protocol.CleanText`, 64 bytes); never the payload or signature.
- PKCE with `S256` is enforced on all OAuth/OIDC authorization requests.
- ID tokens require provider signature, issuer, audience, expiry, and one-time nonce verification before claims are trusted.
- `Provider.VerifyLogout` (`backchannel.go`, OIDC providers only) reuses the ID-token verifier, then requires `iat`, `sub` or `sid`, the back-channel logout event as a JSON object and no `nonce`; a present `typ` must be `logout+jwt`. Every failure is `ErrInvalidLogoutToken`. `IdentityClaims.SessionID` and `IssuedAt` carry the ID token `sid` and `iat` so sessions can be ended by them. Configured OIDC providers share one cached flow per issuer, client ID and secret (`cachedOAuthFlow`), so discovery runs once (a failure is retried after 30 s) and the verifier's key cache persists; `strongJWKSTransport` answers a JWKS refetch within a minute of the last one from the last accepted set, because go-oidc refetches for every token whose signature fails and the logout route is anonymous. That cache lives for the process, so every test IdP behind a configured provider (here and in `internal/api`) serves under a unique issuer path (`"/" + rand.Text()`): `httptest` reuses ports, and a reused issuer URL inherits another test's discovery and keys. `TestVerifyLogoutToken` holds one rejection case per rule.
- OAuth discovery, authorization URLs, PKCE parameters, code exchange, and token verification are delegated to `golang.org/x/oauth2` and `coreos/go-oidc`; application code only maps verified claims.
- SAML assertion parsing is not implemented locally; metadata XML uses `encoding/xml` and no ACS route is exposed until a maintained SAML service-provider library is configured.
- Directory webhook payloads must carry a signed `event_id` (1..128 bytes) and the user's `id` (1..255); timestamps are accepted only within `store.DirectoryEventWindow` (five minutes). The event applies inside `ApplyDirectoryEvent`: a seen `event_id`, or a timestamp older than the last applied event for the same subject, is `store.ErrStaleEvent`. Seen IDs and per-subject watermarks live in the database (migration 41) so a restart reopens no replay window. They commit in the same transaction as the account change and session revocation, so a failed or cancelled event leaves nothing behind and the provider's retry applies (`TestKySignOnWebhookAppliesEachEventOnceAndInOrder`, `TestKySignOnWebhookRetryAppliesAnInterruptedDeactivation`). Only `ErrNotFound` from the subject lookup means "no local user"; any other error fails the event. Status or role changes revoke the user's sessions.
- The webhook writes accounts only through `store.DirectoryTx` (`UpdateUserIdentity`: username, email, display name, role, status; `DeleteUser`), never credential or MFA columns, and never calls the `Store` from inside the event's transaction.
- Every external username passes `auth.ValidateUsername` (3..64 of `[A-Za-z0-9._-]`). `LocalUsername` replaces an invalid claim at creation with `sso_` plus 16 hex of SHA-256(provider, NUL, subject); a webhook rename to an invalid name is ignored while the rest of the event applies (`TestKySignOnWebhookNeverUsesAnInvalidUsername`).
- External identity never selects or grants a tenant. SSO sign-in and the directory webhook create or update the global account (`role`, `status`) only; they never write organization memberships or organization groups, and an externally supplied `admin` role is platform authority with no tenant access. Deactivation denies tenant access live through user status and leaves the membership grant untouched, so reactivation restores what the organization administrator granted; deletion removes the account and its grants, and a re-provisioned account is a new identity that must be granted again. External status changes and deletions bypass the last-administrator guard, which governs membership writes and local deletion: a person the IdP removes must lose access even if they are an organization's sole active administrator. The change applies and each organization left without an active administrator gets an `organization.last_admin_lost` audit row; it has no in-product membership write path until the IdP reactivates the account or a platform repair route exists (tracked in `docs/authorization-matrix.md`; pinned by `TestKySignOnWebhookRemovesAnOrganizationsLastAdministratorAndAudits` and `TestExternalDeactivationCanLockOutAnOrganization`). Provider- or group-to-membership mapping does not exist; if it is ever added it must be an explicit, audited organization-level setting. `TestExternalIdentityNeverGrantsTenantAccess` in `internal/store` pins this through the real webhook client.
