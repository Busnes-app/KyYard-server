# Storage Layer

## Purpose
Provides the unified Database Abstraction Layer (DAL) supporting pluggable backends (SQLite zero-CGO default and PostgreSQL enterprise) with automated dialect-aware migrations.

## Ownership
Owns data models, store interfaces (`UserStore`, `SessionStore`, `DeviceStore`, `GroupStore`, `AuditStore`, `SettingsStore`, `TenancyStore`), dialect translations, and schema migrations.

## Local Contracts
- `InitializeLocalDocker` is trusted startup-only bootstrap: atomically create an approved `ep_local_docker` in the initial organization’s Local environment, its public key and audit record. The `local_docker_initialized` settings marker serializes initialization and survives endpoint/environment deletion; restarts never replace keys, restore revoked authority or regrant membership. Return the last stored inventory generation for reconnect. Existing SQLite snapshots cover these rows without new tables.
- Migration 5 creates organizations, fixed-role/status memberships, environments and organization-local groups. Legacy SCIM groups remain global identity data and confer no tenant membership. Composite group/member foreign keys enforce same-organization references; deleting a membership cascades its group links, so rejoining does not restore them.
- Tenant roles are `organization_admin`, `environment_admin`, `operator`, `developer`, `read_only`. Global `User.Role=admin` remains platform authority and is not a tenant role. Raw persistence methods are trusted bootstrap/management helpers. HTTP routes use the authorized `ReadOrganization`, `ReadEnvironment`, `ListEnvironments`, `AddEnvironment`, `UpdateEnvironment`, `RemoveEnvironment`, `ReadAudit`, `ListMembers`, `PutMembership` and `RemoveMembership` methods. `ListMemberOrganizations` is the one identity-scoped read: it takes the authenticated user's ID and returns only that user's active memberships.
- Every environment/group operation requires its organization ID; names are unique within that organization. `GetMembership` returns status for management; permission checks must additionally require both an active membership and an active user. No global-user/SCIM role implies tenant access.
- `Tenancy.Initialize` runs after account bootstrap, once per database: it grants initial organization administration to the active local admin named `admin`, otherwise the oldest active local admin (creation time then ID). With users but no eligible local admin, it completes without a grant; future administration must explicitly add membership. With zero users it fails and rolls back. Other organizations never receive implicit memberships.
- Bootstrap claims its singleton marker, inserts the membership and records `organization.bootstrap` in one transaction. Concurrent calls serialize on the marker; failed calls retry. Restarts and account resets never regrant removed or disabled memberships. SQLite capsule snapshots include the tenant tables and marker automatically.
- `CompletePasswordChange` atomically compares the old password, updates a flagged local account, clears the flag, deletes sessions/MFA challenges/device pairings and records `auth.password_changed`. Session/MFA issuance locks the same user row against the verified hash; MFA challenges persist the creation-time password hash, and consumption returns that snapshot to reject stale completions. Migration 4 discards preexisting challenges because their credential snapshot is unknown.
- `ResetAdminPassword` reactivates a local administrator with the replacement flag set and shares the atomic grant purge and audit path with `CompletePasswordChange`; it also works for disabled accounts.
- `store.Open(ctx, cfg)` initializes and auto-migrates the configured database backend.
- SQLite defaults to WAL mode. Every connection DSN independently enables foreign keys even when custom tuning pragmas are supplied; open verifies `PRAGMA foreign_keys=1` and fails closed on conflicting options. Tenant reference/cascade guarantees depend on this check.
- PostgreSQL queries are rebound dynamically from standard positional parameters.
- MFA challenges and device pairings are consumed with database state transitions that permit exactly one successful use.
- Recovery-code hash updates use optimistic concurrency so simultaneous redemption cannot reuse a code.

- `withTenant` (mutations) locks the acting membership before checking live user status, password-replacement state, membership status and the named action from `internal/permissions`; PostgreSQL uses `FOR UPDATE` on the user/membership join, SQLite takes its single writer lock with a no-op membership write so a concurrent revocation waits instead of racing. `readTenant` (reads) performs the same checks on a plain snapshot with no lock and no write. Keep authorization, scoped SQL and successful audit in one transaction. Revocation cannot overtake an authorized mutation. Sessions are authenticated per request against the live user row and password replacement revokes them, so there is no separate credential snapshot.
- A caller with no membership in the named organization gets `ErrForbidden` and no audit row: the URL scope is unverified, and a tenant row there would let any account write into another organization's history without bound. Members' denials and failures are recorded in their organization.
- Migration 6 labels historical audit rows `platform`/`unknown` without inventing tenant attribution. New tenant events carry organization/environment, actor (`user_id`), target (`resource`), correlation, action, result and time; audit scope IDs deliberately have no foreign keys so deletion preserves history. Failed operations roll back and log a separate failure/denial without SQL errors, names, bodies or credentials. Audit-write failure aborts successful operations.
- Migration 7 adds `endpoints` (unique name per organization, composite foreign key to its environment with `ON DELETE RESTRICT`), `endpoint_keys` (hex public key, state `pending_review`/`approved`/`retired`) and `agent_enrollment_tokens` (SHA-256 of a 32-byte token, 15-minute life, `consumed_at`). `CreateEnrollmentToken` needs an environment in scope, records the agent image reference the operator was handed (`agent_image`), and returns the raw secret once. `Enroll` is agent-facing: it verifies the proof of possession under the enrollment context (`internal/agent/protocol`), consumes the token with one conditional `UPDATE` so exactly one concurrent caller wins, creates the endpoint `pending` bound to the token's organization, environment and runtime, keeps only the known fact keys (4 KiB total, 255 bytes per value) and refuses, for names and fact values alike, control characters, Unicode line/paragraph separators and bidi controls (`displaySafe`, shared with environment names), so no agent-supplied text can forge or reorder a line in the approval dialog or a log, and audits `agent.enroll` as actor `agent:<endpoint>`; every refusal is `ErrForbidden`, a name clash `ErrAlreadyExists`. `ApproveEndpoint` requires the reviewed fingerprint to be the pending key and a pending age under 24 hours (older reads as `expired`); `RejectEndpoint` and `RevokeEndpoint` are the one terminal transition, retiring keys. `RemoveEnvironment` refuses with `ErrInUse` while a non-revoked endpoint remains, then deletes revoked history with the environment.
- Migration 17 adds `reference` to `endpoint_commands`: an image action stores its reference there and leaves `container_id` empty, because a row that kept an image reference in the container column would read as a container to everything downstream.
- Migration 16 adds `endpoint_commands`: durable intent, written before the frame goes out. `CreateCommand` authorizes the permission its action needs (`container.operate` for start, stop and restart; `container.destroy` for remove), requires a stated `expects.state` for destructive actions and a `confirm` matching the container's name as the last inventory recorded it (comparing the request against itself would attest to nothing, and an endpoint that has reported no inventory has nothing to confirm against). The command then travels as the container **ID** that confirmation resolved to, never the name: a name is a label the runtime reassigns, so a compose recreate between the inventory and the execution would otherwise confirm one container and destroy another; destructiveness follows the permission rather than a parallel list, so a future action given `container.destroy` inherits both requirements; accepts only Docker's own name/ID grammar for the container (`displaySafe` is the wrong gate for a value that becomes part of a URL: it permits a slash, a query and a fragment), binds organization, environment and endpoint, and refuses with `ErrEndpointOffline` unless the endpoint is active. `SettleCommand` writes an outcome only while one is absent, so the first answer wins; `AbandonCommands` settles everything dispatched and unanswered as `unknown` when a session ends. `Prune` ages out settled commands after `CommandRetention` (7 days) and never touches an unsettled one, because a command whose outcome nobody knows is the record an operator most needs.
- Migration 9 adds `endpoint_events` (severity info/high, kind, details, acknowledged_at) and `endpoint_capabilities`. `RotateEndpointKey` verifies the current approved key's signature over the new key, refuses pending/revoked endpoints, refuses while an unacknowledged `duplicate_connection` event exists (`ErrRotationBlocked`) or a live pending key exists (`ErrRotationPending`), retires an expired pending key (7 days), inserts the new key as `pending_review`, records a high `rotation_pending` event naming both fingerprints, and audits `endpoint.rotate` with both. `AcknowledgeEndpointKey` (authorized, `endpoint.enroll`) approves exactly the named unexpired pending key, retires every other key and acknowledges the event. `AgentIdentity(endpoint, fingerprint)` returns `ErrKeyPendingReview` for a live pending key, `ErrKeyRetired` for retired or expired keys, and `ErrForbidden` for revoked/expired endpoints before looking at keys. `SetEndpointCapabilities` replaces the set (at most 64 display-safe strings, 4 KiB total; reads apply the same limit). `RecordEndpointEvent` refuses unsafe kind/details text and keeps one unacknowledged event per kind per endpoint (migration 11's partial unique index on `(endpoint_id, kind) WHERE acknowledged_at IS NULL`, inserts `ON CONFLICT DO NOTHING`, so parallel writers cannot slip past a prior read): a repeat while one stands is dropped, so a flood of one kind cannot grow the table or push other alerts out of the ten the endpoint view shows. The endpoint view's `pending_fingerprint` hides keys past the seven-day window.
- `AcceptInventory` refuses a generation more than an hour ahead of the server clock and records that refusal as a high-severity endpoint event so a bad clock cannot silently pin the inventory; approval and revocation reset `inventory_generation` and delete the stored snapshot, which is the operator's way out of a stuck endpoint.
- Successful reads write no audit row except the actions in `auditedReads` (`organization.audit.read`, `organization.members.manage`), which are low-volume and are what an incident review wants.
- `Usage`/`Budget`/`Pressure` are the disk budget (docs/retention-policy.md): `cmd/server`'s prune loop calls `EvaluatePressure` each pass with the rows that pass freed. The level rises to `PressureDegraded` at 95 % of `KY_RETENTION_DISK_BUDGET` and `PressureStopped` at 100 %, but only while usage is still growing, and any pass clears it. `Usage` is cheap rather than exact (SQLite pages minus the freelist; PostgreSQL's database size), and counts data `Prune` cannot reclaim, so a byte-only release would latch for the life of the server; the throttle that results is reported every fifteen minutes while the condition lasts. `Prune` shortens the raw sample window to one hour under either, because refusing writes alone never gives space back. Nothing in the audit path consults pressure.
- `RollUp(ctx, since)` summarises ended hours into `container_rollups` (migration 15) before the raw window drops them, covering only hours started at or after `since` so a pass costs one or two hours rather than the table; `cmd/server` passes the whole raw window on its first pass, then two hours, under a 30-second deadline because SQLite serves the process from one connection. A recompute may only widen an hour: pruning erodes the oldest in-window hour from below while the loop still runs over it, so the upsert lands only when it was computed from at least as many samples as the row it would replace. Without that, what survives the raw rows describes the hour's last minute. A reading the runtime would not answer for (-1) is counted in neither average nor peak, and an hour holding only those reports -1, so "no data" survives the summary. Summaries are pruned at `RollupRetention` (7 days), or `DegradedRollupRetention` (24 h) under disk-budget pressure so they give space back as the raw window does; the raw rows go at six hours, so a week of history costs 168 rows per container instead of 10,080. `ReadRollups` is an authorized read scoped like the raw one, capped at 200 rows.
- Migration 12 adds `container_samples`, migration 13 its `(endpoint_id, observed_at, container_id)` index and migration 14 `restart_count` (default -1, the runtime declining to answer, which rows written before it cannot tell from zero either); migration 11 (the open-event unique index) belongs to the rotation slice. It adds (primary key endpoint, container, observed_at). `RecordSamples` bounds the frame (1000 samples, display-safe container IDs), re-stamps skewed observations, drops samples inside a container's 50-second cadence (so about 360 rows per container per window whatever an agent sends), scopes cadence lookups to the frame's containers, probes the 100,000-row ceiling without scanning the whole table, and returns `ErrSampleBudget` when capacity is exhausted; the WebSocket reports `samples_budget_exhausted` and stays open, while malformed frames still return `ErrInvalid` and close the connection. `LatestSamples`/`ReadSamples` are authorized reads scoped like inventory; `Prune` deletes samples older than six hours and acknowledged events older than seven days in batches of 5,000 per store per pass, and `cmd/server` runs it every minute until a pass removes nothing (docs/retention-policy.md).
- Migration 10 adds `endpoint_inventory` (one row per endpoint: generation, observed_at, received_at, snapshot JSON). `AcceptInventory` checks the generation and stores the bounded snapshot (`MaxSnapshotBytes`, 1 MiB) in one transaction; `ReadInventory` is an authorized read scoped to organization and optional environment.
- Successful reads through `readTenant` no longer write an audit row (M4 decision in `docs/authorization-matrix.md`); denied and failed reads still do, and mutations are unchanged.
- Migration 8 adds `endpoints.inventory_generation`. The agent-session helpers are trusted and identity-keyed, never session-keyed: `AgentIdentity` returns the endpoint and the key its state allows (approved, or pending_review while pending); `AcceptInventory` applies only a higher generation and moves approved/offline to active; `TouchEndpoint` records heartbeats; `MarkEndpointOffline` only demotes active; `EndpointState` is the live check per frame; `RecordAgentConnect` audits with actor `agent:<endpoint>`.
- Membership management requires `organization.members.manage`. `PutMembership` upserts a fixed role/status for an existing user; `RemoveMembership` deletes. Both first lock the organization row (`FOR UPDATE` on PostgreSQL; SQLite already holds its single writer lock), so membership changes within one organization serialize, then count administrators whose membership and account are both active inside the same transaction and roll back with `ErrLastAdmin` at zero. This blocks the acting administrator from demoting, disabling or removing the last administrator, including concurrently with another; it does not cover platform-level account disablement, which `internal/store` users must handle separately. Membership audit rows carry the target user ID as `resource` (`withTenantTarget`); the organization stays in `organization_id`.
- Tenant audit reads filter organization (and optional validated environment), require organization administration and exclude platform history. Lists use bounded pagination (1–200, default 50 at HTTP).

## Child DOX Index
None.

- `OpenLogTarget` authorizes `container.logs`, refuses an endpoint that is not connected, and resolves the identifier against the last inventory the way a destructive command does, answering with the container ID the stream must name. It is a read that writes an audit row (`auditedReads`): log bodies are never stored, so the record of who read one is the only trace there is.
