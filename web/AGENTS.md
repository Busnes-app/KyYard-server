# Web

## Purpose
React 19 + TypeScript + Vite PWA for fleet operations, provider sign-in, recovery and administration.

## Ownership
Owns user interface components, service worker caching, PWA installation manifests, and frontend theme switching.

## Local Contracts
- Adopted configuration offers on-demand Deployment preflight with 25 services/page, full reported image/target IDs and fixed blocker messages. Always state deployment is unavailable and runtime configuration remains unverified. Mapped services offer a single native modal live inspection using the authorized endpoint API. Compare container/image/creation identity to the preflight target; display only validated redacted facts, discard results on close/scope refresh, abort dismissed requests and never retry automatically. Keep running-container image separate from desired image; selected facts do not establish configuration parity. IDs are observations, not deployment pins; port checks cannot detect host processes or unreported bindings. Hide observations if the selected adoption changed. No apply action.
- Adopted configuration offers an on-demand Deployment plan panel (`ApplicationDeploymentPlan.tsx`), gated on the deployments read alone; only the plan form beneath it additionally gates on the mapping read. Typed project confirmation posts instance/mapping-version/revision to mint a plan, 25 services/page showing pinned image ID, repository digest (or "No repository digest reported"), replaced container/image identity and secret reference counts only. States expiry and that planning again replaces the earlier plan; always states nothing is executed here. A `Revision to plan` selector offers `latest_revision..1` (default latest) and posts the chosen `revision`; below latest it shows the fixed reapply warning (own saved environment values, data written since not reversed, mapping reviewed against the latest). The panel shows the instance's current and previous revision (0 as "none") and a "Deployment history" table of the instance's rows newest first (25/page: kind, revision, state, applied by, applied, settled) with a per-row "Show steps" toggle reusing the result section. A `remove` row's plan renders its container list (service, name, container ID) instead of the services table; its progress uses the same polling and result section, and a denied removal precondition advises refreshing the inventory and re-adopting a container recreated outside KyYard rather than planning again. An application with no instance (removed or released) offers a read-only "Deployment history" toggle (`ApplicationHistory`) listing all its rows. `knownBlockers` (`ApplicationPreflight.tsx`) is the one parser for a 409 `blockers` list. `409` blockers map through the shared preflight `messages`; any other blocked/unknown outcome disables re-planning until refresh.
- A `planned`, unexpired plan offers "Apply deployment": a second typed confirmation naming the application, revision and endpoint states that containers will be replaced and nothing rolls back. On `202` the panel polls `GET .../deployments` directly (never through the shared resource, which would unmount the panel) every 5 s while state is `applying`, until three minutes past the row's `deadline` (15 minutes from the first tick when it has none) or 3 consecutive fetch failures, then shows "Status updates paused; refresh to continue." A settled row shows state, a fixed-text detail (only recognized prefixes render; anything else stays hidden), a 25-row step table (service, step, outcome, fixed detail) and the new container identities. Explanations key on the row state first: `unknown` (host may or may not have acted), `timed_out`, and `failed` with no result (never sent to the host); then on the failing step: `denied` at `precondition` keyed on its detail (container gone, container changed, its image gone, otherwise configuration the definition cannot describe), the pinned image missing, and `failed` (previous container renamed `.kyyard-prev-<id>` on the host). Server-fixed details (`the connection ended`, `no result arrived`, `the endpoint disconnected`, `the host's result`) are recognized prefixes. The panel states that planning executes nothing; it does not call an applyable plan inert. `501`, `403` and named `409` codes (`deployment_in_progress`, `adoption_changed`, `endpoint_offline`, `deployment_not_sent`) map to fixed messages; error bodies are never rendered. No retry, no rollback control.
- Adopted configuration offers “Map services to containers”: explicit owned-ID choices, at most one container per service and one service per container, unmapped option, 25 services/page, full container/image identity and typed project confirmation. Never auto-select from labels. Submit reviewed instance/version/digest and replace the whole map. Show definition-revision mismatch; removed service assignments clear only on save. Failures/unknown outcomes block repeated save until refresh/review; instance replacement requires Applications refresh.
- Application configuration has a saved-revision selector and a separate full-definition “Save new revision” form. Always submit the observed latest head and all Compose values; do not prefill plaintext secrets or silently copy omissions. Confirm the named application/revision and no runtime effect. Clear sensitive input on success/cancel/scope change. Conflict/unknown outcomes block further saves until Applications refreshes; cancel/reopen alone cannot reset that block.
- Adopted application configuration offers on-demand “Compare with host”. Show desired/adopted revision separately, inventory receipt time, explicit unknown/unavailable states, immutable ownership differences and advisory service/image-reference observations. Paginate services/containers at 25 rows; hide comparison if its instance differs from the selected adoption. Never describe matching image references as matching image content, or missing labels as absent services.
- Container rows use a compact native Actions disclosure. Port mappings group matching host/container/protocol tuples while retaining every reported bind address, and distinguish unpublished ports. Select pickers use full-width themed option highlights where customizable native selects are supported; older browsers retain native controls.
- Applications distinguishes drafts from adopted snapshots. Adoption selects an authorized environment host/project, shows the server preview (25 containers/page) and requires typed exact project confirmation; POST carries its digest. Unknown/refused writes block repeated submission until refresh/review. Release confirms readable application, host and project and submits the exact instance ID. An adopted instance also offers "Remove application": fixed text naming the containers stopped/removed and what is kept (named volumes, images, saved revisions), typed project confirmation, POST `removal` `{instance_id, confirm}`; `202` refreshes Applications and shows "Removal sent; watch Deployment history for progress."; 403, 501 and 409 codes (`endpoint_offline`, `deployment_planned`/`deployment_in_progress`, `deployment_not_sent`, `adoption_changed`, `removal_too_large`) and `preflight_blocked` blockers (`unadopted_project_containers`, `apply_outcome_unknown`) map to fixed texts and clear the confirmation so the operator may retry; only 5xx or network failure (unknown outcome) blocks until refresh; bodies are never rendered. An application with `removed_at` is labelled "Removed {date}", may be discarded, and offers only the adoption panel (re-adoption revives it); mapping, preflight and plan panels appear once it has an instance. Switching application/host/project discards its preview. Ownership-read failure must not label projects unmanaged or enable draft discard. Adopted project labels describe the saved snapshot; only recorded immutable IDs are marked adopted, and replacement containers are not silently claimed.

- Environment resources separate Hosts and Applications. Applications lists paginated saved drafts, imports a bounded explicit Compose subset, inspects reference-only configuration, and confirms discard at the observed revision. Import never deploys/adopts. Keep YAML only in component memory; clear on success, explicit clear, resource switch or scope change. Unknown writes disable further changes until the operator checks drafts; diagnostics never echo source/server text.
- Use the Ky palette system with a desktop sidebar and compact mobile navigation. Operational content comes before administration. Single-membership installations automatically use their authorized scope and show no organization name or selector; existing multi-membership accounts retain explicit access-scope switching. Visible administration uses Environments, Members and Audit history. Backend tenant IDs, routes and authorization remain intact. Keep theme controls in Settings. Shared spacing, focus styles, responsive tables and bounded dialogs live in `styles/theme.css`.
- Home exposes existing container actions directly, retaining server authorization, observed identity, confirmation and CSRF. Host pages default to Containers and separate Projects, Images, Networks, Volumes, Activity and Details with explicit resource buttons. Container/image text and controls must remain reachable at mobile widths; tables become labeled rows rather than forcing actions offscreen.
- Logs open in a native modal dialog; Escape/close/unmount releases the reader. Resource-tab changes unmount their controls. Key environment/endpoint pages on full route scope so enrollment tokens, filters and open streams cannot follow navigation to another host/environment.
- Settings separates Appearance, Sign-in, Recovery and Storage. Load provider configuration only when Sign-in is selected. Environment audit/member administration is reached through links rather than embedded under everyday host controls.
- Endpoint Compose discovery groups only the current authorized container snapshot by exact project name. Projects show recorded adoption separately from discovery; expanding/filtering makes no request or runtime mutation. Show observed running/container counts, preserve snapshot freshness and partial-inventory warnings, and reset the filter across endpoint scope changes or when a refreshed project disappears. Render project identity in full as isolated text; arbitrary labels/configuration are not part of project inspection.
- Container controls expose a native modal dialog (focus trap, Escape/close disconnect) with an explicitly confirmed terminal with a required container user and shell executable. The terminal emulator (`@xterm/xterm`, lazily loaded) sends the CSRF token in its first WebSocket message, never in URLs, and binds every later frame to the returned stream ID. No automatic reconnect or execution retry. Input/output chunks are 32 KiB; display writes and socket backlog are bounded to 256 KiB and scrollback to 1,000 lines; overflow disconnects. Unmount/context change releases the socket and emulator. Resize controls bound rows/columns to 1–512. Container escape sequences cannot open links or set application HTML, titles or clipboard contents. Exit status is distinct from an unknown attachment close.
- Home-page guidance presents local Docker as automatic in the standard installation; manual enrollment is for additional hosts. Empty inventories with no runtime version report Docker unavailability and socket/service guidance rather than claiming the host has no containers.
- Endpoint image controls pull explicit tags/digests and remove immutable image IDs after a fresh server-inventory preview and full-ID confirmation. Stale/incomplete dependency data or known container dependents block the preview. The agent rechecks before deletion; no force or automatic retries. Unknown submissions/results remain blocked until the operator checks activity and refreshes. The UI does not accept registry credentials.
- Home lists one selected host’s container inventory with 25 rows per page, search across its full reported snapshot, host selection and host pagination (20/page). Host resource tables also page at 25 rows. Reset paging on search/project/scope changes and clamp when inventory shrinks. Preserve per-host error/freshness states, direct container controls and endpoint links. Action confirmations include the sanitized human-readable host name and endpoint ID. Pagination is shown only when needed. `/endpoints` lists hosts; environment enrollment appears before environment settings. No SCIM or mobile-pairing UI remains.
- Settings offers provider configuration through admin-only `/api/settings/sso`, callback URLs from the server's advertised origin, and the shared theme swatches. Login renders only the public provider list.
- Endpoint container controls use immutable IDs and observed image/state preconditions. Removal first fetches the server preview and requires the full observed name. Commands are never retried automatically; recent activity remains accessible for unknown outcomes.
- Container logs support bounded reads, search, timestamps, download and SSE follow. Browser display retains 256 KiB; follow closes on error without automatic reconnection, and unmount/filter changes cancel the reader. Server notices are separate from container output during follow.
- A signed-in user with `must_change_password` sees only password replacement and sign-out. Replacement uses `secureFetch`, returns to login after session revocation, and never exposes the normal navigation before completion.
- Login shows local setup/SSH/TLS guidance for HTTP installations and offers SSO only when enabled.
- Site branding uses Lucide’s shipping-container outline in the header, login, favicon and install icons; retain its rounded line-art style and theme color inheritance inside the app. Static icon assets carry the Lucide license and are rasterized from the same geometry.
- Product title, PWA name, and pre-settings fallback name are `KyYard`.
- Strict TypeScript type safety without unused imports.
- `theme.ts` carries the fifteen KyPost/KyDNS palettes. Settings shows visual swatches; header and login have no upper-right theme dropdown, by user preference. Apply before React renders, persist under `kyyard-theme`, synchronize theme changes across tabs, and never write a personal theme to instance settings.
- Authenticated state-changing requests use `secureFetch` so the `ky_csrf` cookie is mirrored into `X-CSRF-Token`.
- Navigation is path-based (`src/router.ts`, no router dependency): `/`, `/endpoints`, `/backup`, `/settings`, `/organizations/{org}`, `/organizations/{org}/members`, `/organizations/{org}/audit`, `/organizations/{org}/environments/{env}`. Segments are limited to 64 safe characters; anything else is the not-found screen. `Link` renders real anchors with `aria-current` and leaves modified clicks to the browser. Deep links survive sign-in because the path is untouched while `Login` is shown, and the service worker serves the app shell for offline navigations.
- Access-scope switching lists only the caller's own memberships from `GET /api/organizations` and re-reads when the current organization changes. `<main>` is keyed on the organization ID, so every tenant screen's state is discarded on context change; there is no client-side tenant cache.
- Tenant screens read through `useTenantResource` and show exactly one of loading / denied (401, 403) / not found (404) / offline (network failure) / error, with a retry where retrying can help. Writes go through `tenantWrite` on `secureFetch`; `409 last_administrator`, 403, 404, 409 and network failure map to fixed user-facing messages; any other failure shows only the status code, never server text. Malformed percent-escapes and dot segments in the path land on the not-found screen.
- `/organizations/{org}/endpoints/{endpoint}` (`pages/EndpointPage.tsx`) shows the endpoint's facts, key, capabilities and the stored inventory (containers, images, networks, volumes) with counts; "no inventory yet" (404) is distinct from an empty host; the status line names the generation, how long ago the server received it, flags staleness past three minutes, clock skew past five minutes, and any truncated lists. The containers table carries a Usage column from the latest sample per container: a running container with no sample reads "no data", a first sample with no CPU interval reads "cpu —", and a stopped container a dash; zero is shown only when it was measured. Endpoint names in the environment list link to it.
- The environment screen owns endpoints (`components/Endpoints.tsx`): "Enroll a host" mints a token through `secureFetch` and shows the returned installation command, its scope/restart note, expiry and Docker-socket disclosure once, never refetching it; a details section retains the token for source installs. HTTPS installations get one remote Docker run/link command; HTTP-only installations explain the required reachable HTTPS address. Refresh hosts reloads pending enrollments after the operator starts the agent; endpoint names pass through `displayName` (control characters stripped, clamped to 64) before any confirmation text; approve confirms with the full fingerprint and posts exactly that fingerprint; reject and revoke confirm their consequences; terminal states (`revoked`, `expired`) show no actions. A pending rotation shows both fingerprints (approved and pending) and an "Acknowledge rotation" button whose confirmation carries both in full; other high-severity alerts (`duplicate_connection`) render with their details and a Clear button. `409 environment_in_use` maps to a message telling the operator to revoke endpoints first.
- `Backup.tsx` warns for as long as `database_driver` from `/api/backup/status` is not `sqlite`: only the SQLite path can snapshot a database into a capsule, so a Postgres deployment makes no capsules at all.
